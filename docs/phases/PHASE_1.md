# Phase 1 — Auth, Users and Roles

1.1 Server core: env additions (JWT secrets, token TTLs, cookie settings, client URL); User and RefreshToken models with indexes; hashing utilities; register (student or mentor), login, refresh (rotating, hashed refresh token in an httpOnly Secure SameSite=Lax cookie; reuse of a revoked token revokes the whole family), logout, me, verify-email, resend-verification, forgot-password, reset-password, change-password; authenticate and requireRole middleware; stricter rate limits on auth routes; Zod schemas; EmailProvider interface with console fallback and SMTP (nodemailer), plus verify, welcome and reset templates.

1.2 Server extras: Google ID-token login (google-auth-library; skip gracefully if GOOGLE_CLIENT_ID is unset); PATCH /users/me; DELETE /users/me (soft delete and anonymise); `npm run seed:users` creating verified dev accounts admin@prepant.test / Admin@12345, student1@prepant.test / Student@12345 and mentor1@prepant.test / Mentor@12345 (refuse to run in production); Supertest + mongodb-memory-server tests for register, login, refresh rotation, reuse detection, verify, forgot and reset, and 401/403 role guards.

1.3 Client: Zustand auth store with the access token in memory only; silent refresh on app load; Axios 401 interceptor (one refresh, then log out); RequireAuth and RequireRole guards with redirect-back; pages /login, /signup (role choice, consent checkbox, password-strength meter, Google button), /forgot-password, /reset-password/:token, /verify-email/:token and a verification-pending screen with resend; header user menu; /app/settings (profile, time zone, change password, delete account); minimal protected placeholders at /teach and /admin that show the role; React Hook Form + Zod with inline errors and toasts; all text through i18n keys; component tests for the forms.

1.4 Verify and document: run the full acceptance flow; update docs/API.md and README (how to run, seeded accounts); update PROGRESS.md and DECISIONS.md; `git tag phase-1`.
